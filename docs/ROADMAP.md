# Roadmap: gaps found and what v0.3 did about them

I searched the code for TODO/FIXME markers (there were none) and reviewed the README's
"Known limitations", the settings that did nothing, and the export presets. The table
lists every gap found, what v0.3 did about it, and what's still open.

| # | Gap | Status in v0.3 |
|---|---|---|
| 1 | Only one map | **Done.** 4 maps (Sunset Scrapyard, Frostbite Harbor, Neon Rooftops, Temple Ruins), a map picker with live top-down previews, and "Random". The host's choice is used by every player in LAN and online games. |
| 2 | No way to choose a weapon | **Done.** Loadouts: you pick a starting weapon (or Random, or Crates only) on the Play screen, in the multiplayer room or on the respawn screen. Bots get random loadouts when a player picks one. |
| 3 | The music volume slider did nothing (no music) | **Done.** A procedural music track for the menu and for each map, synthesised in code. |
| 4 | No gamepad support | **Done.** Standard gamepad bindings and focus on the Play screen's START button. Menus also work with a gamepad (Godot's built-in UI navigation). |
| 5 | Machine gun got most of the kills | **Done.** It now has 26 rounds × 3.5 damage (was 30 × 4). |
| 6 | No app icons or splash for the stores | **Done.** Full-resolution icons for Android (adaptive + legacy), iOS (1024 App Store icon) and web, a 1920×1080 boot splash, and Google Play store graphics, all generated by `tools/make_art.py`. |
| 7 | No way to play in a browser without building it yourself | **Done.** A GitHub Actions workflow builds the web version on every push and publishes `main` to GitHub Pages. GitHub Pages has to be switched on once (see the README). |
| 8 | Android build never produced | **Done (in CI).** The same workflow exports a signed debug APK as a downloadable artifact. Real devices are still untested. |
| 9 | No CI | **Done.** Every push and PR runs all test suites, including LAN and online (mock) multiplayer. |
| 10 | Build instructions were thin | **Done.** The README has step-by-step web, Android and iOS guides. |
| 11 | Test runner didn't catch scripts that compile with errors | **Done.** `tests/compile_all` now checks that each script can be instantiated. |
| 12 | Tests were included in exported builds | **Done.** The export presets now leave out `tests/`. |
| 13 | Online play untested against a real Supabase project | **Open.** Needs your Supabase URL and anon key. The online code only ran against the local mock server. |
| 14 | Mobile builds never run on a phone | **Open.** Needs a device. The Android APK comes from CI, and iOS needs a Mac with Xcode. |
| 15 | No host migration or joining a match already in progress | **Open.** It needs a state hand-off protocol and is the largest remaining networking item. |
| 16 | AI never uses the kicker jumps | **Open.** Low priority. |
| 17 | Sound and music haven't been listened to by a person | **Open.** They were generated and level-checked (no clipping), but the build machine has no speakers. |
| 18 | 3D art is simple low-poly built from code | **Open (optional).** For richer models, music or voice lines, see [ASSET_PROMPTS.md](ASSET_PROMPTS.md). |

## Suggested next steps

1. Run one real online room with a free Supabase project, and play a LAN game on two phones.
2. Download the Android APK from the CI run and install it on a phone. Build iOS on a Mac
   (README → iOS).
3. If you want richer visuals or audio, generate the assets in
   [ASSET_PROMPTS.md](ASSET_PROMPTS.md). Each one replaces a code-built piece
   (for example, `KartModel` loading a `.glb` instead of building boxes). That is a small
   code change per asset, listed next to each prompt.
4. Host migration, or letting players join a match in progress.
